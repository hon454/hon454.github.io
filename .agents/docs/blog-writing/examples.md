# 짧은 문체 예시

공개 손글에서 문체 특징이 분명한 부분을 골라 맞춤법과 띄어쓰기만 최소한으로 정리했다. 사실을 재사용하는 템플릿이 아니라 문제 제시, 판단 강도와 호흡을 참고하는 자료다.

## 문제를 제목에서 드러내기

- `다른 프로세스에 디버거를 붙일 수 없는 문제 해결하기`
- `신규 UI의 Rider에서 Edit Solution Configuration이 보이지 않는 경우 해결 방법`

제목만 보고 대상과 현상을 알 수 있다. 모든 제목을 질문형이나 자극적인 문구로 바꾸지 않는다.

## 현상을 바로 제시하기

> 사내 프로젝트를 언리얼 엔진 4.27-Plus에서 5.3.1로 마이그레이션하니 다수의 에셋에서 다음과 같은 경고 메시지가 발생하기 시작했다.

배경을 길게 깔지 않고 환경과 발생 현상을 한 문장에 둔다.

## 출처 기반 내용은 강도를 낮추기

> 윈도우에서는 디버거가 실행 중인 프로세스에 연결될 때 500개 모듈의 심볼만 로드하도록 제한된다고 한다.

직접 확인한 시스템 사양처럼 단정하지 않고 출처 기반임을 어미로 남긴다.

## 해결 확인은 짧게 끝내기

> 위와 같이 구조체의 모든 변수에 `UPROPERTY` 매크로를 추가하면 해결된다.

같은 내용을 다시 요약하거나 의례적인 맺음말을 붙이지 않는다.

## 개인 글의 짧은 반응

> 아니, 이건 Rider와 관련된 문제가 아니잖소?

개인 경험 글에는 상황을 쌓은 뒤 짧은 반문이나 자조적 반응이 들어갈 수 있다. 이런 표현은 원문에 있을 때 보존하며 새로 창작하지 않는다.

## 대조

- 피함: `오늘은 설정 충돌 문제에 대해 자세히 알아보겠습니다.`
- 선호: `프로젝트 설정을 바꿨지만 실행 결과에는 적용되지 않았다.`

- 피함: `결론적으로 이 설정은 매우 중요한 핵심 인사이트를 제공합니다.`
- 선호: `설정 파일을 명시한 뒤 다시 실행하니 변경 내용이 적용됐다.`
