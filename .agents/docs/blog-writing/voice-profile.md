# hon454 블로그 문체 프로필

이 문서는 이 저장소에서 사용하는 블로그 문체의 단일 기준이다. 작성과 윤문 지침은 이 프로필을 해석하며, 다른 프롬프트·Skill·Slack 원문을 별도 문체 원본으로 사용하지 않는다.

## 근거와 신뢰도

문체 근거의 가중치는 다음 순서로 둔다.

1. 2023년 문제 해결 글과 개인 경험 손글
2. 직접 경험과 판단이 분명한 이후 기술 글
3. Velog의 손글 추정 문제 해결 글
4. Slack에서 관찰한 판단 순서와 완곡 표현

Slack은 표면 어미, 문장 길이, 예문을 가져오는 자료가 아니다. AI 관여 여부를 완전히 판별할 수 없으므로 사고 순서와 판단 강도를 확인하는 낮은 가중치의 보조 신호로만 사용한다. 외부 문서 주석, 코드, 과거 글의 오탈자도 모방하지 않는다.

## 한 문장 정의

문제를 바로 제시하고 실제 구현이나 경험을 근거로 원인과 선택지를 설명하며, 필요 이상으로 감정이나 결론을 부풀리지 않는 실용적 기록체다.

## 사고 전개

- 현상이나 핵심 제약을 먼저 말한다.
- 환경과 조건은 문제를 이해하는 데 필요한 만큼만 적는다.
- 직접 확인한 사실, 출처 기반 내용, 추론을 구분한다.
- 코드, 오류, 설정 경로, 재현 단계와 실제로 바꾼 항목을 추상적인 교훈보다 우선한다.
- 자료가 있을 때만 예외, 버전 조건, 실패 조건과 대안을 덧붙인다.
- 해결되면 결과를 짧게 확인하고, 거창한 결론 없이 참고 자료로 넘어가거나 끝낸다.

짧은 해결 메모에는 전체 순서를 강제하지 않는다. 현상과 수정, 확인된 결과만으로 충분할 수 있다.

## 문장과 판단 강도

- 기술 글은 `-다/-한다/-된다`체가 기본이다.
- 직접 확인한 동작과 제약은 짧게 단정한다.
- 추론은 `-것 같다`, `-로 보인다`, `-라고 한다`처럼 강도를 낮춘다. 실제 불확실성을 문체 결함으로 오인해 없애지 않는다.
- 중간 길이 설명문과 짧은 결과문을 섞는다. 리듬을 위해 정보 없는 장문이나 다른 판단 어미를 만들지 않는다.
- `때문에`, `하지만`, `대신`, `경우에는`, `이후`, `위와 같이`처럼 원인·조건·대안을 실제로 표시하는 연결은 허용한다. 반복이 흐름을 가릴 때만 줄인다.

## 기술 표기

- API, 클래스, 함수, 파일명, 제품명과 업계 표준 용어는 원형을 유지한다.
- 코드 식별자는 inline code로 구분한다.
- 첫 등장 원어 병기는 독자에게 실제로 도움이 될 때만 사용한다.
- 코드나 화면 뒤에는 제공된 사실 범위 안에서 그 의미나 필요한 조건을 짧게 설명한다.
- 쉬운 한국어를 장식용 영어로 바꾸거나 정착된 기술 용어를 억지로 번역하지 않는다.

## 구조와 형식

- 제목은 대상과 문제·오류·발생 조건을 직접 드러내는 경향이 강하다.
- 짧은 글은 소제목 없이 끝내도 된다.
- 단계, 선택지, 체크리스트는 목록이 기능적일 때 유지한다.
- 상세 기술 글의 소제목은 독자가 증상·환경·원인·해결을 찾는 데 도움을 줄 때만 사용한다.
- 굵은 글씨, 이모지, 느낌표와 장식적 대시는 거의 사용하지 않는다.

## 감정과 유머

- 기술 글에서는 감정을 거의 드러내지 않는다.
- 개인 경험 글에서는 상황을 쌓은 뒤 짧은 반응이나 자조적 유머로 끊을 수 있다.
- 원문에 있는 유머는 보존하지만 새 유머, 감정과 경험을 만들지 않는다.
- 비유는 거의 사용하지 않으며, 설명 기능이 없는 비유를 추가하지 않는다.

## 피할 표현과 구성

- `오늘은 ~에 대해 알아보겠습니다.`
- `지금부터 자세히 살펴보겠습니다.`
- `결론적으로 매우 중요합니다.`
- `도움이 되셨기를 바랍니다.`
- `핵심 인사이트`, `강력한`, `혁신적인`, `놀라운` 같은 홍보성 표현
- 모든 문단을 같은 길이와 구조로 정리하는 것
- 이미 설명한 내용을 결론에서 다시 길게 요약하는 것
- 근거 없는 경험·원인·수치·버전·비유를 보태는 것
- Slack식 존댓말, 메시지 분절, `ㅋㅋ`, `ㅎㅎ`, `;;`를 기술 글에 이식하는 것

## 현재 신뢰도

- 기술 문제 해결 글과 짧은 메모: 높음
- 장문 기술 설명: 중간~높음
- 개인 경험·에세이: 낮음~중간
- 현재의 대화 태도와 완곡 표현: 잠정
- 구체적인 윤문 선호: 아직 낮음. AI 초안과 사용자가 직접 고친 최종본이 쌓이면 갱신한다.
