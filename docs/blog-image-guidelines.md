# Steady Spiral 블로그 이미지 지침

## 적용 조건

이 문서는 **사용자가 블로그 이미지의 생성이나 수정을 명시적으로 요청했을 때만** 적용한다. 커버, 본문 개념 삽화, 기술 도식 모두 같은 조건을 따른다. 생성 도구를 사용하는 경우뿐 아니라 SVG나 코드로 이미지를 직접 만드는 경우도 포함한다.

- “이 글의 커버를 만들어 줘”, “이 절을 설명하는 이미지를 추가해 줘”, “이 도식을 수정해 줘”는 해당 이미지 작업의 요청이다.
- 글 작성·윤문·검토·게시, 업스트림 반영, 기존 이미지 첨부, 스타일 상담이나 지침 작성만으로는 이미지 생성이 허용되지 않는다.
- 에이전트가 이미지가 필요하다고 판단해도 자동으로 생성하거나 기존 이미지를 교체하지 않는다. 필요한 경우 제안만 할 수 있으며, 실제 제작은 사용자의 명시적 요청 이후에 진행한다.
- 요청한 용도와 범위 안에서 제작한다. 커버 요청을 본문 삽화 제작까지 확대하지 않는다. 이미지 제작 요청 자체를 글 게시나 배포 요청으로 해석하지 않는다.

일반 글쓰기 작업의 필수 단계로 이 문서를 읽거나 이미지 제작을 수행하지 않는다. 사용자의 명시적인 선택과 수정 요청은 아래 기본 스타일보다 우선한다.

## 기준 이미지

경로는 저장소 루트를 기준으로 한다.

| 역할 | 경로 |
| --- | --- |
| 캐릭터의 형태와 색상 | `public/assets/images/logo/steady-spiral-color.png` |
| 커버의 표현 스타일 | `src/assets/images/posts/replication-rpc-ordering-cover.webp` |
| 정확한 관계를 설명하는 기술 도식의 예 | `src/assets/images/posts/replication-rpc-lost-update.webp` |

제작 전에 해당 용도의 기준 이미지를 실제로 확인한다. 이미지 생성 도구가 참조 이미지를 지원하면 캐릭터 원본과 필요한 스타일 기준을 함께 전달한다. 텍스트 설명만으로 원본을 대신하지 않는다. 기준 파일이 없으면 위치를 확인하고, 임의의 새 캐릭터로 대체하지 않는다.

캐릭터 원본은 정체성의 기준이며 커버는 재질·조명·장면 표현의 기준이다. 커버에 나온 봉투, 숫자, 길과 물음표는 해당 글의 소품이므로 다른 글에 그대로 반복할 필요가 없다. 임시 첨부 경로는 장기 참조 경로로 사용하지 않는다.

## 캐릭터의 정체성

- 짙은 초록 몸체, 라임색 나선 껍질, 둥근 두 더듬이, 아이보리색 눈과 작은 입을 유지한다.
- 두툼하고 둥근 실루엣과 원본의 얼굴·몸체·껍질 비율을 따른다. 같은 Steady Spiral 캐릭터로 알아볼 수 있어야 한다.
- 글에 맞춰 표정, 자세, 시점, 크기와 소품을 바꿀 수 있다. 여러 마리가 등장해도 같은 캐릭터의 변형으로 표현한다.
- 원본 로고나 favicon 자체를 다시 디자인하거나 덮어쓰지 않는다. 새 장면은 별도 블로그 이미지 자산으로 만든다.

## 용도 선택

사용자가 요청한 범위 안에서 전달할 내용을 먼저 정하고 형식을 선택한다.

| 용도 | 목적 | 캐릭터 활용 |
| --- | --- | --- |
| 커버 | 글의 주제나 핵심 문제를 한 장면으로 보여 준다 | 주인공으로 활용한다 |
| 본문 개념 삽화 | 하나의 추상적인 개념을 직관적인 상황으로 풀어 준다 | 행동과 소품에 설명 역할을 부여한다 |
| 본문 기술 도식 | 순서, 조건, 상태와 관계를 정확히 설명한다 | 이해에 도움이 될 때만 등장시킨다 |

요청 대상에 코드·표·실제 화면이 더 적합하면 그 이유와 대안을 설명한다. 본문의 모든 절에 이미지를 넣거나, 기술 도식마다 캐릭터를 배치할 필요는 없다.

## 커버와 개념 삽화의 표현

기본 스타일은 부드러운 점토 모형 같은 3D 일러스트다. 따뜻한 아이보리 배경, 부드러운 조명과 접지 그림자를 사용하고, 소품도 단순하고 둥근 형태로 만든다.

- 글의 핵심 문제나 개념 하나를 중심 장면으로 표현한다. 소품마다 글 내용과 연결되는 역할이 있어야 한다.
- 달팽이라는 이유만으로 모든 주제를 느림이나 지연에 연결하지 않는다. 글에 실제로 등장하는 관계를 바탕으로 장면을 설계한다.
- 커버에 제목과 긴 문장을 기본으로 넣지 않는다. 설명에 꼭 필요한 짧은 숫자나 기호는 사용할 수 있다. 불필요한 장식 문자나 워터마크를 추가하지 않는다.
- 정확한 문자와 식별자가 필요한 경우 직접 편집 가능한 방식으로 작성하거나 별도로 배치하고, 최종 결과에서 표기를 검증한다.

## 기술적 정확성

본문의 주장과 조건을 먼저 확인한다. 비유가 본문에 없는 인과관계나 보장을 만들어서는 안 된다. 순서·손실·재시도·동시성·상태 전이는 본문의 조건에 맞춰 표현하고, 여러 경우가 가능한 동작을 하나의 필연적인 순서로 그리지 않는다.

예를 들어 기존 RPC 커버의 봉투와 `1 → 3 → 2`는 전달 순서의 혼란을 표현하는 비유다. 이를 모든 RPC가 순서 없이 처리된다는 설명으로 사용하지 않는다. 구체적인 순서 보장 범위는 본문과 기술 도식에서 구분한다.

정확한 문자, 코드 식별자, 화살표와 수치가 핵심인 도식은 SVG 등 직접 편집 가능한 방식으로 작성한다. 캐릭터가 흐름을 가리거나 가독성을 떨어뜨리면 생략한다. 비유의 한계와 예시의 전제는 필요한 경우 캡션이나 인접 본문에 적는다.

## 구도와 저장소 적용

- 커버의 기본 제안 비율은 16:9이며 사용자의 요청과 실제 표시 영역에 맞춰 조정한다.
- 포스트 카드의 중앙 크롭을 고려해 얼굴, 주요 소품과 핵심 관계를 중앙에 모으고 충분한 여백을 둔다. 바깥에는 잘려도 의미가 유지되는 배경을 배치한다.
- 목록형·그리드형 카드와 모바일에서 주제가 읽히는지 확인한다. 본문 이미지는 축소해도 문자와 관계가 읽혀야 한다.
- 새 자산은 해당 글 주변의 저장 관례를 따른다. 글에서 참조할 이미지는 `src/assets` 또는 기존 글의 이미지 폴더에 두고, 안정적인 소문자 영문·숫자·하이픈 파일명을 사용한다.
- 글에 적용하는 범위도 사용자 요청을 따른다. 적용할 때는 실제 경로와 프런트매터 또는 Markdown 참조를 확인하고, 본문 이미지에는 전달하는 정보를 설명하는 대체 텍스트를 작성한다.
- 렌더링·콘텐츠·자산을 변경했다면 저장소의 검증 지침을 따른다. 스크린샷 첨부는 별도 명시적 요청이 있을 때만 수행한다.

## 결과 검토와 재사용

최종 결과에서 캐릭터 일관성, 글과의 연결, 기술적 오해, 크롭과 작은 화면 가독성을 확인한다.

생성 도구를 사용한 작업은 최종 자산 경로, 참조 이미지, 사용한 프롬프트와 주요 수정 사항을 재사용할 수 있게 작업 기록에 남긴다. 기록이 이미지 제작과 함께 블로그 본문에 들어갈 필요는 없다. 한 글의 소품이나 일회성 요청을 공통 규칙으로 바꾸지 않고, 사용자에게 반복해서 승인된 방향만 공통 지침에 반영한다.

## 요청별 입력 예시

사용자의 명시적 제작 요청을 받은 뒤 아래 정보를 글과 요청에서 정리한다. 전달할 개념과 반드시 구분할 조건이 장면 설계보다 우선하며, 새 사실을 만들어 빈칸을 채우지 않는다.

```text
대상 글: <글 경로 또는 제공된 본문>
요청 범위: <커버 / 특정 절의 개념 삽화 / 기술 도식>
전달할 개념: <독자가 이미지에서 이해할 내용>
반드시 구분할 조건: <순서 보장 범위, 상태, 예외 등>
장면: <캐릭터의 행동과 소품, 필요하면 제작 시 설계>
출력 및 적용: <비율, 파일 형식, 글에 연결할 범위>
```
