# 콘텐츠 분류 기준

카테고리는 글의 주된 독자 의도를 나타내고, 태그는 글을 다른 글과 연결하는 핵심 기술·주제만 나타낸다. 둘 다 선택 사항이며, 분류가 글의 탐색성을 높일 때만 사용한다. 제목이나 본문에 이미 충분히 드러나는 세부 명칭을 모두 태그로 복제하지 않는다.

## 카테고리

카테고리를 지정할 때는 다음 값 중 하나를 사용한다.

- `언리얼 엔진`: Unreal Engine 자체의 기능, 구조, 문제 해결
- `C++`: 특정 엔진에 한정되지 않는 C++ 언어 주제
- `개발 도구`: IDE와 개발 생산성 도구
- `개발 인프라`: CI/CD, 빌드 인프라, 컨테이너와 운영 환경
- `블로그`: 블로그 구축, 운영, SEO와 브랜딩
- `커리어`: 채용, 조직 경험과 경력 회고
- `개발 이야기`: 개발 문화, 제품 개발과 프로젝트 회고

## 태그

- 태그를 지정할 때는 포스트당 1~5개를 사용한다. 태그가 필요하지 않으면 생략하거나 빈 배열을 사용한다.
- 영문 소문자 kebab-case를 사용한다. 예: `garbage-collection`, `build-configuration`.
- 넓은 기술 영역 1개, 핵심 주제 1~2개, 문제 유형이나 구체 기술 1개 정도로 구성한다.
- 카테고리의 canonical slug와 완전히 같은 태그는 사용할 수 없다. 예를 들어 `언리얼 엔진` 카테고리에서는 `unreal-engine` 태그를 붙이지 않는다.
- 다른 카테고리에서 Unreal Engine을 함께 다루는 글에는 `unreal-engine` 태그를 사용할 수 있다.
- 대소문자나 유사어만 다른 태그를 새로 만들지 않는다.
- 한 번만 쓰이는 태그는 제품명, API, 시스템처럼 검색 가치가 분명한 고유 용어에만 사용한다.

태그는 Google의 순위용 키워드 목록이 아니다. 정확한 내부 분류, 관련 글 추천, Pagefind 검색 메타데이터와 `BlogPosting.keywords`를 위한 의미 정보로 관리한다.

## 카테고리 URL

화면과 메타데이터에는 한국어 표시 이름을 사용하고, 아카이브 필터 URL에는 다음의 안정적인 slug를 사용한다.

- `언리얼 엔진` → `unreal-engine`
- `C++` → `cpp`
- `개발 도구` → `development-tools`
- `개발 인프라` → `devops`
- `블로그` → `blog`
- `커리어` → `career`
- `개발 이야기` → `development-stories`

현재 한국어 표시 이름과 명시된 별칭을 쿼리에 사용한 URL도 같은 카테고리로 해석하며, 브라우저 주소는 안정적인 slug로 정규화한다. 이전 분류 체계의 URL은 호환 대상으로 삼지 않는다.
