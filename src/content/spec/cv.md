### Shotloom

2026.04 - 2026.08 / Rust, Bevy, WebAssembly, WebGPU, React, TypeScript, Tauri

- **개요:** 사용자별 서버 GPU 세션에 의존하던 Unreal Engine과 Pixel Streaming 경로를 대체하는 브라우저 3D 편집기. 캐릭터 동작과 카메라를 편집하고 결과를 CineV의 제작 흐름으로 연결
- **담당 범위:** 캐릭터와 카메라 편집, 문서 모델, 저장과 복원, 생성 서비스 연동

#### 편집 트랜잭션과 저장 구조

- **과제:** React UI, Rust 문서 모델, Bevy 런타임으로 나뉜 구조에서 명령 거절이나 시간 초과 시 세 계층의 상태가 어긋날 위험
- **판단:** 계층 간 브리지 계약에 트랜잭션 수명주기와 Undo/Redo 명령을 추가하고, 드래그 중간값 대신 사용자의 조작 단위로 변경을 확정하는 BundleEditor 경로 설계
- **수행:**
  - 번들 형식 스펙을 Rust 문서 모델로 구현하고, 컬렉션을 구조 공유 자료구조로 바꿔 스냅샷 복사 비용 제거
  - 조작 단위 트랜잭션, 명령 거절과 시간 초과 시 롤백, Undo/Redo 런타임 구현
  - 자산 등록과 편집 대상 생성을 같은 트랜잭션에 묶어 되돌리기 후 참조와 자산이 따로 남지 않도록 처리
  - 브라우저 복구 화면과 진단 문구, autosave와 명시 저장의 응답 구분, 선택 상태를 문서 본문과 분리 저장
- **결과:** 명령 거절과 시간 초과를 조작 단위로 롤백하는 공통 편집 경로로 전환, 로컬에서 캐릭터, 포즈 후보, 클립과 카메라 키를 저장한 뒤 다시 열어 편집 상태 복원 확인

#### 카메라와 포즈 키프레임 전환

- **과제:** 키를 프레임 번호로 식별해 시간을 옮기면 선택 대상을 잃고, 위치와 회전을 묶어 저장해 일부 축만 편집하기 어려운 키프레임 구조
- **판단:** 프레임과 독립적인 키 ID와 속성별 키를 두고, 회전 횟수의 의미가 있는 카메라는 오일러 각, 관절은 쿼터니언으로 보간
- **수행:**
  - 키프레임 모델, 평가기, 편집 명령, 편집 UI와 저장 형식 버전 4 이전 구현
  - 편집 명령에 문서 변경 버전과 트랜잭션 ID 검사를 붙여 중복 적용과 일부 키만 저장되는 상황 방지
  - 스크럽 입력을 진행 중 요청 하나와 최신 대기 입력 하나로 제한
- **결과:** 속성별 카메라 키를 편집, 평가, 저장하는 저작 기능으로 전환, 이전 저장 형식의 원본을 남기는 업그레이드 제공, 50회 반복 스크럽에서 점진적 지연과 메모리 증가 미재현

#### 생성 서비스 통합

- **과제:** 스토리보드의 장면 구성 입력(S2M)과 포즈 생성 서비스(Text2Pose)의 결과를 편집 가능한 장면으로 변환하고, 편집 결과를 CineV로 반환
- **판단:** 브라우저 프리뷰와 CLI, 서비스가 같은 규칙으로 입력을 해석하도록 번들링과 장면 구성, 검증 정책을 공유 Rust 코드로 모으는 방향 선택
- **수행:**
  - S2M 입력을 장면과 자산으로 변환하는 번들 컴파일러, Text2Pose 후보의 선택과 클립 적용 구현
  - CineV 진입 시 작업 ID와 입력을 검증하고, 런타임과 자산 준비 뒤 장면을 구성하며 늦게 끝난 이전 요청이 다른 장면을 바꾸지 않도록 처리
  - 생성과 결과 저장을 분리해 저장 실패 시 같은 결과 재전송
- **결과:** 개발 배포 환경에서 CineV 진입 시 인물 2명, 소품 4개와 카메라의 자동 구성, 영상 생성 결과 이미지의 스토리보드 반영 확인

#### AI 에이전트 개발 체계

- **과제:** CINEVStudio 후속 개발을 빠르게 진행하면서 React UI, Rust 문서 모델, Bevy 런타임을 함께 바꾸는 기능의 범위와 완료 기준 관리
- **판단:** 요구사항을 Linear 이슈, 명세, ADR(설계 결정 기록)과 테스트로 구조화하고, AI 에이전트를 개발 과정 전반에 활용하는 방식 선택
- **수행:** 에이전트 작업 가드레일과 hook을 추가하고 ADR 31건 작성, 반복 절차를 2026년 5월 공개한 개인 오픈소스 Grimoire로 정리
- **결과:** 여러 계층을 바꾸는 기능을 의존 작업으로 나눠 구현과 독립 검토를 분리하는 개발 절차 정착, 카메라와 포즈 키프레임 전환을 12개 의존 작업으로 진행

#### 그 밖의 업무

- VRM 캐릭터 가져오기와 런타임 로딩, SpringBone 좌표 보정, 뷰포트 선택과 이동, 회전 기즈모 구현

### CINEVStudio

2024.06 - 2026.04 / Unreal Engine 5, C++, UMG, Sequencer, MovieScene, HTTP, ONNX

- **개요:** AI가 구성한 장면을 사용자가 편집하고 영상으로 출력하는 Unreal Engine 5 기반 제작 도구
- **담당 범위:** 콘텐츠팀의 액션 데이터 작성부터 AI 결과 해석, 타임라인 편집, 저장과 재생까지 잇는 클라이언트 개발

#### 액션 데이터 작성 구조 전환

- **과제:** 애니메이션 구간과 상호작용 설정을 DataTable과 Notify에 타입과 인덱스로 맞추고, 문자열 파라미터를 별도 설계 문서와 대조해야 하는 입력 구조
- **판단:** 액션 정의는 DataAsset으로 분리해 필요한 요구조건만 타입별 구조체로 추가하고, 모션 구간과 이벤트 시점은 애니메이션을 보며 AnimComposite에서 편집하는 구조 선택. 조건 값의 조합에는 구조체를, 이벤트별 동작 확장에는 UObject를 사용
- **수행:**
  - 데이터 타입과 실행 경로 전환, 변환기 구현, 전환 절차 문서화
  - 작성한 데이터를 생성 단계에서 실행용 에셋으로 모아 런타임이 애니메이션 에셋에 직접 접근하던 부분 분리
  - 기존 검증 프레임워크에 액션 데이터 행 검증기와 메타액션 대비 대상 데이터 검증 추가
  - 애니메이션 0프레임의 기준 본에서 액션 시작 위치 오프셋을 자동 계산
  - 데이터 규칙과 전환 절차를 기획, 애니메이션, TA, QA 직군과 공유
- **결과:** 제작자가 기억해 맞추던 조건 관계를 입력 구조와 검증기로 대체, 콘텐츠팀 제작 가이드에 에셋 작성 절차 반영

#### AI 행동 해석과 생성 모션 적용

- **과제:** 외부 AI 서비스가 지정한 행동과 대상을 현재 월드에서 실행 가능한 액션으로 변환하고, 생성 모션을 타임라인 편집에 연결
- **판단:** 외부 입력을 읽는 파싱과 월드 상태를 판단하는 해석 계층을 분리하고, 후보의 시작 위치 검증과 경로 점수 평가를 하나의 파이프라인으로 통합

  - 샷 JSON 파서를 초기 상태, 카메라, 블록, 섹션 단위로 나누고 타입 검사 도입
  - 캐릭터 배치 위치를 극좌표 샘플링과 근접도 점수로 고르는 위치 보정 구현
  - Text-to-Motion 요청의 성별, 배치 단위 병렬 처리와 일부 실패 시 성공 결과 보존, 기존 ONNX 본 변환을 결과에 적용하고 최적화
  - 생성 모션의 선택, 타임라인 적용, Undo/Redo 구현, MotionSet을 별도 파일로 압축 저장하고 원자적 커밋과 롤백 적용
