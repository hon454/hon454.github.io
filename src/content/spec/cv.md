### Night of the Dead

#### 멀티플레이 동기화 최적화

- **과제:** 소유 관계에 따라 거리와 무관하게 전달해야 하는 상태, 접속 시 한꺼번에 보내야 하는 레벨 스트리밍 상태와 기록 데이터, 자주 바뀌는 상태 프로퍼티의 전송량
- **판단:** Unreal Insights 분석을 바탕으로 복제 대상 선정, 전송 데이터 축소, 전송 경로 분할로 나눠 최적화
- **수행:**
  - Replication Graph에서 거리로 연결별 후보를 수집하고, 오너, 팀, 그룹에 종속된 액터는 거리와 무관하게 포함
  - 장착 장비와 무기 부속품, 고용한 NPC, 탑승물은 Dependent Actor로 묶어 부모 액터가 복제될 때 함께 검토
  - 상태가 드물게 바뀌는 아이템, 문, 풀링 좀비에 Net Dormancy 적용
  - 접속 시 보내는 레벨 스트리밍 상태 목록에 커스텀 NetSerialize를 붙여 패키지 경로를 int16 코드와 비트 플래그로 압축
  - 장비 이름 대신 ID를 복제하고 게임 시각은 분이 바뀔 때만 복제하는 식으로 장비 상태, 게임 시각, 웨이브 진행도의 복제를 줄이고, 적용되지 않던 Adaptive NetUpdateFrequency 설정 수정
  - Reliable 버퍼의 여유를 보고 레코드 단위로 나눠 보내는 RPC 스트리밍 라우터를 만들고 지도 안개 동기화를 Fast Array에서 이 경로로 전환
- **결과:** 복제 대상, 전송 데이터, 전송 경로를 나눠 다루는 동기화 구조로 전환, 개발 업데이트 #10, #11, #15, #19와 1.0 정식 출시에 반영. 효과 수치는 측정하지 않음

#### 커스텀 Destructible

- **과제:** UE4의 PhysX 기반 APEX Destruction에서 원인을 알 수 없는 에러가 잦아 크래시로 이어지던 상황. 교체하더라도 파괴 시점에 Destructible 컴포넌트를 만들던 기존 구성(교체형 APEX)의 시각 효과와 성능을 유지해야 함
- **판단:** 소스 엔진으로 PhysX 연동 코드까지 디버깅했으나 남은 분석이 PhysX 바이너리 내부 디버깅이라 드는 시간이 과도하다고 보고, 원인 추적 대신 직접 제어할 수 있는 최소 기능의 커스텀 Destructible 시스템으로 교체. 시각 효과와 성능은 거의 같을 것으로 예상
- **수행:**
  - Blender에서 미리 나눈 조각 StaticMesh를 파괴 시점에 만들고 일정 시간 뒤 제거하는 구조 구현 (2023.04 재구성)

  - 실험 프로젝트에서 동시 파괴 부하 시험의 병목을 Unreal Insights로 조각별 컴포넌트 등록(100개 파괴 시 2,400회)으로 특정하고, 한 프레임에 만드는 조각 컴포넌트 수를 240개로 제한하는 개선안 구현
